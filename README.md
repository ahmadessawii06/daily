# ميزان — التشغيل والصيانة

## التشغيل المحلي

من مجلد `daily` الداخلي، باستخدام Node.js 22.12 أو أحدث:

```powershell
npm ci
npm run dev
```

افتح `http://localhost:3000`. أنشئ حسابًا باسم مستخدم وكلمة مرور.
إذا كان المنفذ مستخدمًا، ينتقل خادم التطوير إلى منفذ متاح ويطبع الرابط الصحيح في Terminal.
بدون `MONGODB_URI` يحفظ الخادم البيانات في `data/accounts.json`، ويُنشئ سر الجلسات في `data/.session-secret`.
احتفظ بنسخة احتياطية من الملفين. التخزين المحلي مخصص لعملية خادم واحدة؛ استخدم MongoDB عند تشغيل أكثر من نسخة.

```powershell
npm test
npm run build
```

أمر البناء يتضمن فحص TypeScript. `npm run preview` يعرض الواجهة المبنية فقط؛ استخدم خادم المشروع لتسجيل الدخول والمزامنة.

## البيانات القديمة

نظام الدخول القديم كان مختلفًا بين المتصفح والخادم المحلي وVercel. لم تُحذف ملفات البيانات القديمة أو بيانات المتصفح.
الحسابات التي كانت محفوظة في المتصفح فقط ليست حسابات خادم قابلة للمزامنة: أنشئ حسابًا جديدًا ثم افتح الإعدادات، نزّل النسخة القديمة، واختر «استيراد لهذا الحساب» إن كانت البيانات تخصك.
الاستيراد يدمج بيانات الإصدار v8 والعادات والمهام المتكررة. النسخ الأقدم متاحة في ملف النسخة الاحتياطية، ولا تُحذف أو تُدمج تلقائيًا.
الملفات القديمة `data/users.json` و`data/days.json` محفوظة كذلك؛ لا تُنقل لحساب جديد تلقائيًا لأن الكود القديم وحده لا يثبت ملكية الحساب.
المهام التي سبق أن حذفها الإصدار القديم فعليًا لا يمكن استرجاعها دون نسخة احتياطية.

## النشر على Vercel أو Netlify

حدد مجلد المشروع الداخلي `daily` كجذر المشروع. أمر البناء `npm run build` ومجلد الواجهة `dist`.
يستخدم الخادم المحلي وVercel وNetlify نفس API في `backend/app.ts`.
أضف في إعدادات بيئة الخادم:

- `MONGODB_URI`: رابط قاعدة MongoDB الفعلية، مع مستخدم يملك الوصول لقاعدة المشروع.
- `JWT_SECRET`: قيمة عشوائية لا تقل عن 32 حرفًا، ثابتة بين النسخ وإعادات النشر؛ تغييرها يلغي الجلسات الحالية.

يمكن إنشاء سر محليًا ثم نسخه إلى إعدادات الاستضافة:

```powershell
node -e "console.log(require('node:crypto').randomBytes(48).toString('hex'))"
```

لا تضع الأسرار في متغيرات `VITE_` أو في Git. في الإنتاج، تعطل قاعدة البيانات يعيد خطأ ويُبقي التعديلات في طابور المتصفح؛ لا يستخدم ذاكرة مؤقتة أو `/tmp` بديلًا عن التخزين الدائم.
الحسابات الجديدة محفوظة في مجموعة MongoDB `accounts`، مع تحديثات مشروطة بالإصدار لمنع فقد التعديلات المتزامنة.
المزامنة تدمج المهام حسب آخر تعديل لكل مهمة، وتنقل سجلات الحذف؛ التعديل الأحدث لنفس المهمة يفوز. العادات والمهام المتكررة تُزامن كقوائم حسب آخر تعديل للقائمة.

اختبارات المشروع تغطي التخزين المحلي وواجهة API وعزل الحسابات وطابور المزامنة ومحوّل Netlify. اختبار MongoDB الفعلي والنشر يحتاجان إعدادات البيئة الخاصة بك.

مرجع إعداد Netlify: [Express on Netlify](https://docs.netlify.com/build/frameworks/framework-setup-guides/express/).
